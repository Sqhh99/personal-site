**6. OpenAI：11 月 18 日说明 Codex 沙箱默认关掉网络，工作区可写但 .git 与 .codex 只读**  
11 月 18 日 OpenAI 工程师 Michael Bolin 发文，说明 Codex 如何在用户自己的环境里跑命令，并由用户控制文件系统和网络边界。文中写，沙箱不把计算搬进另一套虚拟机或容器，而是用各操作系统自己的沙箱设施，约束跑在现有环境里的命令，这样 Mac 上的 iOS 工具链和模拟器不必先复制进 Docker。内置的 `:workspace` 配置写成：工作区里可以写，但 `.git` 和 `.codex` 只读，因此不能直接改 `.codex/config.toml` 或 `.git/hooks` 里的 Git 钩子；文件系统读取放得比较宽，受用户原有操作系统权限约束，代价是机器上其他位置的敏感文件，例如带 API 密钥的配置，仍可能可读；网络默认关闭，用来挡住把读到的数据直接传出去，也因此不能直接下载依赖。文中举了一个沙箱挡不住的例子：智能体可以改本地已安装的包，例如 `node_modules/prettier`；`node_modules` 常常被 Git 忽略，`git status` 不一定看得到；如果编辑器在保存时跑这份 Prettier，恶意代码会在 Codex 沙箱外面执行。子进程继承父进程的沙箱约束，限制沿整棵进程树生效，包括比原进程活得更久的后代。shell 工具可以按条请求不同权限：`use_default` 用这一轮的默认配置，`with_additional_permissions` 在沙箱内扩大访问，`require_escalated` 请求到沙箱外执行。给不给由 harness 按用户偏好决定，可以直接问用户，也可以交给 auto-review。权限配置写在 `config.toml` 的命名配置里，可以从 `:workspace` 派生，对路径给 `read`、`write` 或 `deny`。网络大致三条：`:workspace` 默认全关，`:danger-full-access` 默认直接全开，或者只允许走到一个按域名规则过滤的代理。`codex sandbox` 命令写成可以把同一套沙箱执行接到自己的工具里。这篇是实现说明，不是一份新的入侵报告。对要把「默认沙箱已经让工作区以外的密钥不可读，而且关了网络就没有副作用」写进代理策略的人，现在能核对的是文中写明的宽读取，以及 `node_modules` 那个会在沙箱外执行的例子。

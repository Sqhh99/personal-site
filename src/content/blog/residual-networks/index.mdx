A residual network is usually introduced as an architectural motif: a few convolutions, a line drawn around them, then an addition. The line matters, but the more useful idea is what it changes about the job of each block. A plain block must produce the next representation. A residual block need only produce the correction that should be made to the representation it already has.

That modest reformulation made very deep convolutional networks trainable in a way that stacking more of the same layers did not. It also turned out to be unusually portable: pre-activation, wider blocks, grouped transformations and channel attention all modify the residual branch while preserving the same dependable route through the model, and the same shape reappears in segmentation decoders, in speech models and under every diffusion sampler.

What follows takes the machinery apart. The claims that can be checked in a browser are checked in a browser — the training curves below come from two networks that are actually training on this page, and the propagation curves from actual products of actual random matrices. The claims that cannot be checked here are marked as such.

## The degradation problem

### A deeper network contains the shallower one

Suppose a 20-layer network has learned a useful mapping. A 32-layer network of compatible shape ought, in principle, to do at least as well. There is a constructive argument: keep the first twenty layers, and set the extra twelve to compute the identity. That solution exists inside the larger model's parameter space, and it achieves exactly the smaller model's loss.

So the deeper model's optimum is at least as good as the shallower model's optimum. Any gap that shows up in practice is a gap between the optimum and what the optimiser found.

### The failure is in optimisation, not generalisation

The early plain convolutional networks used in the 2015 experiments often did worse as they became deeper — not only on held-out data, but on the training set. That distinction is the whole diagnosis. A larger gap between training and validation error would suggest overfitting, which is a statement about capacity. Higher *training* error is a statement about search: the optimiser failed to reach solutions the deeper model demonstrably contains.

Watch the plain curve rather than the gap. It does not overfit and it does not diverge — it flattens, and at the deepest settings it flattens somewhere much worse. The optimiser is still descending, on a surface where progress has become expensive, and the extra blocks it was given have not bought anything. The variation between the three initial draws is worth sitting with rather than averaging away. At four blocks the ordering is not even stable — the plain model wins on some draws. Depth is what makes the difference reliable, which is exactly the shape of the original claim.

### What the toy does and does not show

This is a twelve-unit tanh network fitting a one-dimensional curve, not a convolutional network on ImageNet. It has no batch normalisation, no data augmentation and no validation set, and its notion of depth costs microseconds rather than GPU-days.

What transfers is the mechanism, and the mechanism is visible precisely because so much else has been removed. Same width, same depth, same initial draw, same learning rate, same data — the models differ only in whether a block computes $f(x)$ or $x + \beta f(x)$.

That $\beta$ deserves flagging now rather than later. It is the scale on the residual branch, and it defaults to $1/\sqrt{L}$. Set it to 1 with the control and a deep residual network here does not merely train badly, it diverges: the identity route accumulates every branch's output, the sum grows with depth, and the whole thing saturates. This is not a defect of the toy. It is the second half of the story, and section 3.2 comes back to it with measurements.

The original experiments compared plain and residual networks with matched convolutional structure, and batch normalisation was already present in both. The gain was not simply "ResNet added normalisation" — which is worth remembering, because normalisation turns out to be doing more of the work than the 2015 framing suggested.
</MarginNote>

What does not transfer is any quantitative claim. The ratio in the readout is a property of this toy. Read it as a direction, not a number.

## The residual reformulation

### Learning a correction

Let $x$ be the tensor entering a block. A plain stack tries to learn some desired mapping $H(x)$. A residual block writes the same mapping as

$$
y = F(x; W) + x,
$$

where the weighted branch $F$ learns the difference $H(x) - x$. If leaving the representation alone is a good local decision, the branch can move towards zero and the shortcut supplies the identity for free.

The reformulation does not change what the block can express: $F$ ranges over the same function class either way, so the two parameterisations reach the same set of mappings. It changes which mappings are *easy to reach from initialisation*. Near zero-mean random weights, a plain block computes something arbitrary; a residual block computes something close to the identity. If the useful answer at a given depth is "mostly leave this alone, but adjust these few directions", the residual parameterisation starts nearby and the plain one does not.

This does not mean every useful layer is close to identity. Some stages change spatial size or channel count, and some residual functions are large. The claim is gentler: representing a small correction is made cheap wherever a small correction is appropriate.

### What is inside the block

</Figure>

#### The basic block

The basic block used in ResNet-18 and ResNet-34 has two $3\times3$ convolutions. In the original v1 ordering, each convolution is followed by batch normalisation; the first also has a ReLU, and another ReLU follows the addition. When resolution and width are unchanged, $x$ goes around the branch untouched.

Its cost is dominated by the two spatial convolutions, each $9C^2$ parameters at width $C$. That quadratic term is why the basic block does not scale to the widths deeper models want: at $C = 512$ a single $3\times3$ convolution is already 2.4 million parameters.

#### The bottleneck

The bottleneck used in ResNet-50 and deeper models has a $1\times1$, $3\times3$, $1\times1$ sequence. The first pointwise convolution reduces the channel width by four, the middle convolution does the spatial work at that reduced width, and the last expands back to the block's output width. "Bottleneck" describes the narrow middle, not a compressed network output.

The arithmetic is the point. At $C = 256$, a basic block spends $9 \times 256^2 \approx 590\,000$ parameters per convolution; the bottleneck's $3\times3$ operates at width 64 and spends $9 \times 64^2 \approx 37\,000$. The two pointwise layers cost $256 \times 64$ each. The block ends up several times cheaper at the same output width, which is what lets ResNet-50 be deeper *and* smaller than a hypothetical basic-block network of the same width.

#### Where the shortcut stops being free

At a stage boundary the main branch halves height and width while doubling channels. Addition requires matching shapes, so the shortcut uses a strided $1\times1$ projection. It is still a short path, but it is no longer an exact identity, and it is no longer parameter-free — toggle the stage boundary in the figure and the projection's parameter count appears.

There are four of these boundaries in a standard ResNet and dozens of identity shortcuts, so the projections are a small share of the model. But they are the reason the clean claim is "an identity route exists wherever shapes permit", not "an identity route exists". Diagrams that draw every shortcut the same way lose that qualification, and with it the explanation for why the very deepest stacks still benefit from careful initialisation.

## Why the reformulation helps

### The derivative of an addition

For one block, differentiating the residual update gives

$$
\frac{\partial y}{\partial x} = I + \frac{\partial F}{\partial x}.
$$

The upstream gradient therefore has a term that does not pass through the residual branch's weight layers. Across many blocks, the full derivative is a product of such sums, and expanding it produces many routes: long products through learned transformations, shorter mixed routes, and one route that is the identity all the way down.

This is usually where the phrase "gradient highway" appears, and it is where most explanations stop. It is worth going two steps further, because the identity term does not do what the phrase implies.

### Signal propagation is still exponential

Set g to 1 with β = 1 and read the residual curve — it grows, and it grows exponentially. Then switch to β = 1/√L and watch it flatten.">
  <SignalPropagation client:visible />

#### What the measurement shows

Model a block's Jacobian as a random matrix with entries of scale $g/\sqrt{n}$. A plain layer multiplies the squared norm by roughly $g^2$ per block, so the norm after $L$ blocks scales as $g^L$. Unless $g$ sits almost exactly at 1, that is exponential decay or exponential growth, and no amount of depth-independent tuning fixes both ends at once.

A residual block computes $(I + \beta J)$, and because the identity and the random branch are uncorrelated, the squared norm is multiplied by $1 + \beta^2 g^2$ per block. With $\beta = 1$ and $g = 1$ that factor is 2, so the activation norm grows like $2^{L/2}$.

The dashed lines in the figure are those two closed forms; the solid lines are the measurement, averaged over twelve independent draws of the whole stack. They track each other closely and not exactly, which is itself worth noticing — twelve samples of a product of forty random matrices is not many, and the spread between draws A, B and C is the honest error bar.

So the identity path converts a two-sided exponential into a one-sided one. That is a genuine improvement — exponential growth with a well-behaved direction is far easier to control than a product that can collapse to zero — but it is not the removal of the exponential.

#### Why normalisation is not optional

Set $\beta = 1/\sqrt{L}$ and the per-block factor becomes $1 + g^2/L$, whose $L$-th power tends to $e^{g^2}$ — bounded, independent of depth. This is exactly the correction that later work applies by hand: Fixup scales residual branches down with depth, and ReZero and SkipInit put a learnable scalar in front of the branch and initialise it to zero, the $\beta = 0$ setting in the figure.

Batch normalisation inside the branch achieves something similar without anyone naming it as the goal. By rescaling the branch output to unit variance it suppresses the branch relative to the accumulating identity stream, and the effective $\beta$ falls as the stream's variance grows with depth. This is why the 2015 result is not "ResNet added normalisation" but also not independent of it: the identity route and the normalisation are jointly responsible for the depth-independent scale.

The trainer in section 1 carries the same control, and the toy is unforgiving about it. At $\beta = 1$ and twenty blocks the residual network diverges outright — no normalisation, nothing to hold the accumulating stream down. The shortcut on its own does not make a deep network trainable. It makes a deep network trainable *given* something that controls the scale.

### The unravelled view

#### Counting paths

Expanding the product $\prod_{l}(I + F_l)$ over $L$ blocks gives $2^L$ terms, one for each subset of blocks a route passes through. A network of 54 blocks therefore contains about $1.8 \times 10^{16}$ distinct computational paths, and their lengths are exactly binomially distributed: most paths use about half the blocks.

#### Effective depth

Path counts are not the interesting distribution. If traversing one residual branch scales a gradient by a factor $a < 1$, a path of length $k$ contributes about $a^k$, so the gradient mass at length $k$ goes as $\binom{L}{k}a^k$. Summing gives a closed form for the mean length that actually carries gradient:

$$
\mathbb{E}[k] = \frac{La}{1 + a}.
$$

The readout compares this against the summed distribution, and they match. The consequence is the one Veit and colleagues drew in 2016: a very deep residual network behaves less like one deep function and more like an ensemble of many relatively shallow ones. In a 110-layer network they found the effective paths concentrated in the range of roughly 10 to 34 blocks.

This also explains an otherwise odd empirical fact. Deleting a single block from a trained residual network usually costs very little accuracy, while deleting a layer from a trained plain network is catastrophic. Removing one block removes half the paths, but the surviving half is drawn from the same distribution — the network degrades rather than breaking.

<MarginNote>
Stochastic depth trains with this property deliberately: each block is dropped with some probability during training, which shortens the expected path and acts as a regulariser. It is what made networks past a thousand layers trainable at all.
</MarginNote>

### What the shortcut does not do

It does not prevent badly scaled residual branches, dead nonlinearities, unstable normalisation statistics at small batch size, or a poorly conditioned loss. It does not make learning rate schedules unnecessary — very deep residual networks still needed warmup in the original CIFAR experiments.

Nor does it mean gradients literally choose one wire. Back-propagation sums contributions along all computational paths simultaneously; there is no routing decision anywhere in the algorithm. "Gradient highway" is useful language only if the highway is understood as one term in that sum — the term whose coefficient happens to be exactly one.

## Ordering: pre-activation

### Post-activation clips the clean route

The original block applies a ReLU after the addition. That means the value handed to the next block is $\mathrm{ReLU}(x + F(x))$, and the "identity" route from block $l$ to block $l+1$ passes through a nonlinearity that discards half its range. Over a hundred blocks, the composition of a hundred ReLUs is not an identity in any useful sense.

### The v2 unit

ResNet-v2 moves batch normalisation and ReLU in front of each convolution and removes the activation after the sum:

$$
x_{l+1} = x_l + F(\mathrm{BN}(x_l); W_l),
$$

with the activation folded into $F$. Now the recursion unrolls cleanly: $x_L = x_l + \sum_{i=l}^{L-1} F(x_i)$. Every block boundary is connected to every later boundary by an addition and nothing else, in both directions. Pre-activation also changes the role of normalisation — weights receive normalised, activated inputs, while the addition itself stays linear.

### When it matters

The gain is largest exactly where the argument predicts: very deep networks, where a hundred intervening ReLUs is a hundred opportunities to clip. At 50 or 101 layers the two orderings are close, and at 18 layers post-activation is often marginally better. Pre-activation is not automatically superior; it expresses the identity argument more faithfully, and the faithfulness pays off in proportion to depth.

## Other axes of capacity

Once a reliable scaffold existed, depth stopped being the only way to spend computation.

### Width

Wide Residual Networks shorten the model and multiply the channel count in each residual branch. Wider layers expose more features in parallel and use hardware far better than extremely long, narrow chains, because a wide convolution is a large matrix multiply and a deep chain of narrow ones is a sequence of small ones with a synchronisation between each.

The trade is memory and parameters. Activation storage grows linearly with width, and parameter counts grow roughly quadratically when both input and output widths expand — WRN-28-10 has about 36 million parameters against ResNet-50's 25 million, at a fraction of the depth.

### Cardinality

ResNeXt changed a different axis. Instead of one dense transformation, its residual branch performs $C$ transformations of identical topology and sums them. In practice this is a grouped convolution, not a loop over miniature networks.

Watch aggregate width climb while the parameter count stays put.">

The figure's arithmetic is worth stating in full, because it is the argument. The block's parameter count is

$$
512\,Cd + 9\,Cd^2,
$$

which at $C = 1$, $d = 64$ gives 69,632 — the standard bottleneck. Holding that number fixed and solving the quadratic for $d$ at each $C$ recovers the published configurations exactly. As cardinality rises, aggregate width $Cd$ rises with it, from 64 at $C = 1$ to 128 at $C = 32$, because grouping removes the cross-group terms that made the $3\times3$ convolution quadratic in width.

So cardinality is not another spelling of width, and it is not free capacity either: it is a structural constraint that buys aggregate width by forbidding mixing between groups. Comparing ResNeXt models fairly means holding a compute or parameter budget, which is why ResNeXt-50 32×4d is quoted against ResNet-50 rather than against something larger.

### Channel attention

Squeeze-and-Excitation blocks pool each channel of the residual branch to a single number, pass the resulting vector through a two-layer gating network with a reduction ratio of about 16, and multiply the branch features by the learned channel weights before the shortcut addition. Spatial positions within a channel share a weight; this is channel selection, not spatial self-attention.

SE works neatly with residual blocks because it modulates the proposed update without touching the identity route. If a gate suppresses a residual channel, the corresponding shortcut feature still passes. The cost is small in MACs and less small in latency, because a global pool is a synchronisation point in the middle of an otherwise local computation.

## Concatenation is a different answer

### DenseNet's state

A DenseNet layer concatenates *all* earlier features in its block:

$$
x_l = H_l([x_0, x_1, \ldots, x_{l-1}]).
$$

ResNet repeatedly adds corrections into a fixed-width running state. DenseNet preserves earlier features as separate channel groups and lets later layers read them explicitly. Both give short paths from early layers to the loss; they differ in what the state *is*.

### Memory is the real difference

The addition in a residual block is destructive in a useful way: once $F(x)$ has been added, the two summands are no longer separable, and the state stays at width $C$ forever. DenseNet's state grows by the growth rate $k$ at every layer, so a block of $n$ layers ends at $C_0 + nk$ channels and every intermediate concatenation is a live tensor.

That is why DenseNet-121 reaches ResNet-50-like accuracy with a third of the parameters but not a third of the training memory. Parameter count and activation memory are different budgets, and connectivity patterns trade between them. DenseNet is not a kind of ResNet, and neither is a strictly better version of the other.

## The recipe is part of the result

### Training changes that flatter old architectures

Modern "ResNet" numbers reflect training choices that were absent or undeveloped in 2015: better augmentation, much longer schedules, cosine decay, decoupled weight decay, label smoothing, mixup, exponential moving averages of weights, and a redesigned downsampling stem. Applied together, these lift ResNet-50 from about 76% top-1 on ImageNet to about 80% — a larger gain than most of the architectural changes above, on a graph that has not changed at all.

The consequence is not that architecture is irrelevant. It is that a model name identifies a graph, not a method, and a comparison that varies both tells you nothing about either.

### Starting each block near identity

One training refinement belongs to this article rather than to a general list. Zero-initialising the scale parameter of the last batch-norm layer in each residual branch makes every block compute exactly the identity at step zero. The network starts as a shallow model and deepens itself as the branches grow.

That trick is the residual argument taken to its conclusion — and it is the $\beta = 0$ setting in the propagation figure, where the forward and backward curves are flat by construction. If a block is a proposed correction, then the right thing to propose before you have learned anything is nothing.

## What to keep

- Degradation is an optimisation failure. A deeper plain network can fit its *training* data worse than a shallower one, even though the shallower solution sits inside its parameter space.
- The residual update $F(x) + x$ does not change what a block can express. It changes what is cheap to express near initialisation, which is where the optimiser starts.
- The identity term makes the per-block factor $1 + \beta^2 g^2$ instead of $g^2$: a one-sided exponential instead of a two-sided one. Bounded propagation still needs normalisation, or a branch scale that shrinks with depth.
- A residual stack of $L$ blocks is $2^L$ paths with binomial lengths, and the gradient concentrates on the short ones. Effective depth is $La/(1+a)$, not $L$.
- Basic blocks spend their budget on two $3\times3$ convolutions; bottlenecks use $1\times1$ layers to make the central spatial convolution affordable at four times the width.
- Pre-activation removes the ReLU from the identity route, and pays off in proportion to depth. Width, cardinality and channel attention spend capacity on three different axes under one scaffold.
- DenseNet gets short paths by concatenation instead of addition. It trades parameters against activation memory — a different answer to the same question, not the same answer renamed.
- Training recipes now account for several points of ImageNet accuracy. A model name identifies a graph, not an experiment.

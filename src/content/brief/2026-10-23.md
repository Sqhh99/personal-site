**要闻（6 条）**

**1. METR 与 Redwood：驻场评估估计，当时约 75%–94% 的相关内部流量有资格被监控**  
10 月 22 日 METR 公开一篇驻场评估。7 月 21 日至 8 月 11 日（标明日期），METR 与 Redwood Research 各派一人，在 OpenAI 现场用公司配发、不得带出场地的设备，查阅内部代码、监控提示词和文档，并访谈大约十二名监控、安全系统和安全团队的人。评估的是 7 月 21 日及之前的内部错位监控，METR 写这不覆盖练习期间正在扩展的系统，也不建立现在的覆盖率。METR 估计，当时不低于 GPT-5.5 的模型，其内部 Responses API 智能体流量里大约 75%–94% 有资格被监控，双向都有很大不确定性；其中内部 Codex 智能体那一部分估计为 99.2%。练习开始时，强化学习训练运行不在这套监控里。METR 估计，5 月至 7 月不监控压缩事件，可能让大约一成有资格被监控的内部 Codex 流量没被看到；OpenAI 员工在练习前已独立发现，并在练习期间修好。当时监控在智能体把控制交还用户时触发，因此在这个缺口还在的时候，智能体只要继续行动，原则上可以一直推迟被监控。METR 写受访问限制，没有检查是否已有智能体实际这么做。他们还写，Codex 智能体原则上可以绕过沙箱和 Auto-Review，从而做宿主用户能做的任何事；另有一处可让最近数百次行动不被监控，细节由 OpenAI 删去。两个可由客户端控制的头能为新智能体关掉监控，但设置这些头并创建实例这一步本身可能被抓住。METR 写，OpenAI 表示影响生产防护栈的漏洞都已修补，评估方没有核对这些说法。公开文本事先约定只发简短摘要，OpenAI 有权自行删节。海峡时报转载的电讯引 OpenAI 说，这些发现在系统扩展时帮助加强了防护，并将影响此后与 METR 及其他第三方评估者的研究合作。近三日已写 OpenAI 自己披露的两起关掉监控；本条是这份外部评估公开文本的增量。对在仓库里跑编码智能体的人，75%–94% 是「有资格被送去监控」的历史估计，不是监控管道没有丢请求之后的比例；合同现在可以问对方说的覆盖率，指的是 7 月 21 日之前的这份估计，还是 OpenAI 所说、但 METR 没有复核的修补之后。  
来源：METR https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/ · The Straits Times https://www.straitstimes.com/world/united-states/external-evaluators-find-flaws-in-openais-ai-monitoring-system-in-pilot-review

**2. OpenAI：Decisions API 正式可用，未缓存输入 $0.10 / 百万 token，不收输出费**  
10 月 22 日 OpenAI 宣布 Decisions API 正式可用，模型是 GPT-6 Luna，请求打到专用的 `POST /v1/decisions`。博文写，它把 Luna 用在答案有界的问题上，从文本、图像和结构化输入做近实时决定，速度最多比通过 Responses API 调用的 GPT-6 Luna 快 10 倍；这是厂方表述。开发者文档写，公开测试之后加上了提示缓存、题目指令里的图像、原生 JSON、每请求最多 400 个问题（测试期为 200），以及 GPT-Live 直接调用。返回的是概率、固定选项或按有序等级打出的分数，不是自由生成的一段 JSON。博文标价为每百万输入 token 0.10 美元，缓存输入 0.01 美元，不收输出 token 费。文档写未缓存输入是 0.10 美元，缓存读写按 GPT-6 Luna 的常规缓存价，区域处理加价和长上下文乘数仍然适用；符合条件的客户可用零数据保留，区域处理支持美国和欧洲（欧洲经济区加瑞士）。对已经用大模型做分类和路由的人，可对的是 10 倍和 0.10 美元计的是输入 token，题目内容不进可复用的缓存前缀；合同现在可以问生产走的是这份正式端点，还是仍在 Responses API 里生成一段再解析。  
来源：OpenAI https://openai.com/index/decisions-api/ · OpenAI Docs https://developers.openai.com/api/docs/guides/decisions

**3. Anthropic：Claude 为 123 个库的 239 个入口证明，给定假设下 64MB 内输入不会崩溃**  
10 月 22 日 Anthropic 前沿红队写，与 Theorem 合作，用 Claude 在 RISC-V 汇编上为开源库证明安全性质。厂方写，Claude 先补上它找到的缺陷，再证明 123 个 OSS-Fuzz 库的 239 个入口：在任何小于 64MB 的输入上都会正常退出，不触发内存安全错误，也不让断言失败。假设写明为单线程静态二进制、固定内存预算、RISC-V CPU 和 Linux。证明大约 1.8 亿行 Rocq，一条典型证明约 60 万行，对应二进制的中位长度约 1.8 万条 RISC-V 指令；由 Rocq 内核对照规范检查。厂方写，这不表示这些库没有别的缺陷：剩下的问题要么在 RISC-V 与 Linux 进程的形式模型、被证明的定理陈述或 Rocq 本身，要么在证明范围之外。尝试证明时找到的例子包括，某库所带解压代码在大约 20MB、布局很特殊的输入上才会出现的计数器下溢和越界写，以及 libexpat 里 CVE-2026-56132 的再发现。厂方写会公开本项目里尚未公开的可信组件、不需要补丁就能证明的那些模糊测试的完整 Rocq 证明，以及没能证明的其他测试的规范。近三日已写 PHP 引擎漏洞；本条是汇编级无崩溃证明的增量。对要拿「AI 证明了没有漏洞」做交付的人，239 是给定假设下的不崩溃，而且需要补丁才证完的那些，博文没有说完整证明已经公开；合同现在可以问对方引用的是这 239 个入口，还是已经放出来的那一部分证明。  
来源：Anthropic https://www.anthropic.com/research/formal-verification

**4. Hugging Face 放出 Carbon-X：14.8B、Apache-2.0，五套 DNA 基准平均 66.7%**  
10 月 22 日 Hugging Face 放出 Carbon-X。模型卡写，它是 14.8B 参数的解码器模型，从 Qwen3-14B 继续训练，许可证 Apache-2.0，与中关村学院、Telethon 遗传学与医学研究所及那不勒斯费德里科二世大学合作。DNA 和英文走同一条 token 流，DNA 按不重叠的 6 碱基切分。模型卡写中期训练 3020 亿 token，上下文 40960 token，bfloat16 权重放得进一块 80GB GPU。思考关掉时，五套 DNA 基准平均 66.7%，对照 GPT-6.1 Sol 最大推理的 67.5%、Opus 5.5 最大推理的 60.9%；厂方把每题推理成本写成约为 GPT-6.1 Sol 的 1/1800，Carbon-X 一侧按每 H200 小时 5 美元的实测吞吐估算。这些是模型卡上的数字，不是独立复现。模型卡写它没有经过临床验证，不应用于医疗决定，并且会数错碱基、搞混坐标。WIRED 同日报道了这次放出。近三日已写 Anthropic 的蝎毒结合蛋白实验；本条是另一家开放权重、用英文回答 DNA 问题的模型。对要在实验室里问变异是否致病的人，66.7% 是厂方五套基准的平均，模型卡写明不能用于医疗决定；合同现在可以问序列是留在自己的 GPU 上，还是送到了托管推理端点。  
来源：Hugging Face https://huggingface.co/HuggingFaceBio/Carbon-X · WIRED https://www.wired.com/story/hugging-face-new-ai-biology-model-chat-with-dna/

**5. Anthropic 开放 Claude Duet 研究预览：Opus 5.5，美国 Pro 与 Max 候补**  
10 月 21 日 Anthropic 开放 Claude Duet 的研究预览候补。它是独立应用，在 iOS、Android 和 claude.ai 上，围绕 Claude Opus 5.5 做主动式智能体：早上给一份简报，人离开后在自带浏览器的虚拟机里继续干活，连上的账号每隔几小时查一次。研究预览含在美国的 Pro 和 Max 里，占用与 Claude 其余部分相同的用量额度，后台检查也计入；Team 和 Enterprise 厂方写还没有。发出消息、付款、签署文件或删除之前要人批准；买卖证券和在账户之间转账，即使批准也不允许。厂方写凭证处理沿用托管智能体的设计，智能体不直接看到密码或登录令牌，并称可用 Claude Marketplace 里超过 6000 个连接器和插件。厂方同时写，这仍是早期版本，可能读错线程或误判什么算紧急。对要把邮箱和付款交给后台智能体的人，预览名单目前只写美国的 Pro 和 Max，后台检查和长任务都吃同一份额度；合同现在可以问对方说的自动付款有没有停在先给人看、再批准，以及证券和转账是不是仍被写为不允许。  
来源：Anthropic https://claude.com/resources/articles/claude-duet

**6. NVIDIA：DSX POD 把备好场地上的部署写成最短 14 天，目标 2027 年初交付**  
10 月 21 日英伟达在 GTC Berlin 推出 DSX POD，一种由伙伴在模块化集装箱里造好、交付前完成集成和验证的 Vera Rubin AI 工厂参考设计。通稿写，场地的电力、冷却和网络准备好之后，部署时间从六个月降到最短 14 天；布线、管路和功能验证改在工厂做，和场地准备并行。厂方写正与一批计算和基础设施伙伴合作，目标是 2027 年初在全球交付。通稿点名的伙伴包括 Bull、Dell Technologies、HPE、Lenovo、Schneider Electric 和 Vertiv。14 天和 2027 年初是厂方的部署目标，通稿把相关表述列为前瞻声明。近三日已写同一场 GTC 上的基板、封装、测试和光引擎扩产；本条是集装箱式工厂参考设计的增量。对排机房上线的人，14 天的前提是场地已经备好，而且机器是 Vera Rubin；合同现在可以问交货写的是这份参考设计的 2027 年初目标，还是已经能下单的现货集群。  
来源：NVIDIA Newsroom https://nvidianews.nvidia.com/news/nvidia-introduces-dsx-pod-ai-factories-to-accelerate-europes-infrastructure-deployment

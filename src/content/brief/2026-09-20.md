**1. 特朗普宣布组建「AI Force」、再任命 AI 沙皇；白宫仍拒新监管**  
9 月 19 日（周六，美东下午，北京时间已入 20 日）特朗普在 Truth Social 发长帖：将组建「AI Force」，类比其第一任期设立的太空军（Space Force）；「不久」宣布新的 AI「Czar」，「Only High I.Q. individuals need apply」。原句：「We will not in any way hinder or stifle the Growth of this incredible Industry. Rather, we will cherish it, help it, and watch over it, as it grows! However, we will also be looking for BAD, and we can do that, very easily, with our already existing Criminal and Civil Justice System。」他把 AI 写成「下一场工业革命或互联网，甚至更大」，可能占美国 GDP 的 **25%**；并称美国正领先中国，「I intend to keep it that way」。白宫当时未回应记者问询：该机构是军是民、预算、是否需国会立法、人选。CNN / Axios：这是对近两周「实验室谈自愿放缓、加州行政令谈 kill switch」的**联邦口头对案**——承认要盯「BAD」，但执法工具仍是既有刑民司法，不是新的前沿模型安全法。若兑现，这将是第二任 AI 沙皇：风险投资人 David Sacks 今年春天卸任特别政府雇员、改任外部顾问，现主持总统科技顾问委员会。路透社：财长 Bessent 将于 **9 月 20 日（周日）** 在纽约摩根大通总部会见中方何立峰，议题含 AI 安全与经贸；特朗普与习近平会晤定于本周四。对政策/采购侧，不要把一篇社媒帖读成已经有编制、预算或现场核验权——下一轮对账的是「AI Force」落在国防部还是白宫、以及它会不会直接对上加州 N-9-26 的独立核验时间表。

**2. 四名付费用户起诉 Anthropic / OpenAI / SpaceXAI / Google：把「pace the frontier」写成谢尔曼法合谋**  
9 月 18 日（周五，近三日简报截稿后见报；标明日期）北加州联邦地区法院立案 *Buist v. Anthropic PBC*，案号 **3:26-cv-10693**。Bloomberg Law / POLITICO / CBS：原告是四名分别付费订阅 ChatGPT、Claude、Grok、Gemini 的个人（含佛罗里达律师 Charles Buist、Nick Spetsas，加州居民 Christine Bullock，以及律师 Cheyenne Hunt），拟代表全美付费订阅者集体诉讼。被告：Anthropic PBC、OpenAI OpCo LLC、SpaceXAI、Google LLC。诉因是谢尔曼法第 1 条：四家「同意彼此进度应慢于竞争本应产生的水平」，付费用户因此少得到产品改进。时间线写在起诉书里：7 月三家已组工作组谈行业标准机构；**9 月 12 日** Amodei 发 *We Must Pace the Frontier*，约一小时内 Musk 背书、Altman 同意并承诺走「第一步」、Hassabis 称「the right path forward」。原告律师 Nick Rowley：「The antitrust laws do not permit competitors to decide among themselves that competition is too dangerous。」起诉书同时走本身违法 / quick-look / 合理原则三条理论，以抗早期驳回。四家周六均未立即回应。这是对近一周「司法部口头说安全协调不像反竞争、Lehane 说不需要豁免、Amodei 自己写需要窄豁免」的**私人执法增量**：从政策辩论写成可点名的北加州诉状，不是已经认定合谋，也不是停训令。对法务/采购侧，合同与对外口径现在要预留「公开附和放缓」会被读成协议的证据风险；同时也要分清——这是订阅者民事案，不是司法部或 FTC 的执法行动。

**3. Plugin4Shell：四家主流编码 agent 的插件 SHA 钉扎可被绕过；Copilot 披露时仍无补丁**  
9 月 17–18 日（周四/周五，近三日简报未写入；标明日期）安全公司 AIR（Or Nevo / Dor Granat / Niv Hoffman）公开 **Plugin4Shell**：Claude Code、OpenAI Codex、GitHub Copilot、Gemini CLI 在从 marketplace 安装/自动更新插件时，会 `git checkout` 钉扎的 40 位 commit SHA，但**不验证工作树是否真落在该 commit**。攻击者若控制插件仓库，可建一个**与 SHA 同名的分支**并设为默认分支；git 在「同名既是 ref 又是 object id」时优先解析 ref，agent 仍报告「已按钉扎提交安装」。Claude Code 与 Codex **默认后台自动更新**插件，marketplace 把钉扎 SHA 从 benign 的 `aaa…`  bump 到仍 benign 的 `bbb…` 后，攻击者再把默认分支改成恶意内容，已安装用户无需点击即 RCE。GitHub 拒绝 40-hex 分支名，故纯 GitHub 托管的 marketplace 挡得住这一变体；Bitbucket 与自托管 git 允许，而 Anthropic 文档把二者都列为合法 marketplace 后端。Gemini CLI 是另一条路径：`git checkout FETCH_HEAD` 在默认分支就叫 `FETCH_HEAD` 时会丢掉刚 fetch 到的 commit。修复只需一条：`test "$(git rev-parse HEAD)" = "<pinned-sha>" || abort`，且必须写在 agent 里，marketplace 无法单独兜底。厂商响应不齐：Anthropic 于 **2026-06-17** 在 Claude Code **2.1.179** 修好；OpenAI 于 **2026-08-12** 在 Codex **0.146.0** 修好；Google **8 月 4 日**确认不修已弃用的 Gemini CLI，让用户迁到无 SHA 钉扎插件系统的 Antigravity；Microsoft 披露时仍未给 Copilot 发补丁。The Register 转述 GitHub 发言人：GitHub 不允许 SHA 形分支名，「reported vulnerability cannot be exploited on GitHub」；AIR 回应 Copilot 仍支持 Bitbucket 等主机，漏洞仍在。对运行侧，这是编码 agent 供应链的第一类「钉扎看起来生效、实际未校验 HEAD」漏洞：锁 Claude Code / Codex 的人应核对版本号；Copilot 与仍在跑的 Gemini CLI 应关自动更新、只允许 GitHub 主机、或暂时卸插件，而不是一篇披露等于四家已经全部打完补丁。

**5. 阿里发布 Qwen3.8-LiveTranslate：同传 LAAL 2.8 秒→2.3 秒，新增说话人分离与原文译文同帧**  
9 月 18 日 Qwen 官方博文上线（中文媒体 19 日跟进；昨日简报写了同日的 Qwen3.8-Omni-Flash，本条是同传产品增量）。**Qwen3.8-LiveTranslate** 用 Interleave 架构把已听音频与已出译文收成同一条可缓存的音–文交错流；官方称字均延迟（LAAL）从上一代 **2.8 秒**降到 **2.3 秒**（约 **-18%**）。在既有 **60** 种语言输入/文本输出之上新增三项：实时说话人分离（句级归属 + 更稳的音色复刻）、原文与译文同步流式（双语同屏）、长上下文消歧（用人名/术语/指代的前文约束当前句）。结构：Hybrid MoE 的 Thinker–Talker——Thinker 把视频、音频、原文、译文排进同一因果序列端到端产出；Talker 用译文加源音频合成保留原说话人音色的译文语音。评测（厂方自报）：多说话人长音频集 Omnilingua-MSpeaker（**14** 个语向）在忠实度、流畅度、简洁度与 DER 上优于「当前主流实时同传」；公开 FLEURS 音频集 **70** 个语向上，翻译质量 / 平均滞后 / ASR / TTS 四维领先上一代与主流系统。输出语音覆盖 **29** 种语言。API 名 `qwen3.8-livetranslate-flash-realtime`，走 DashScope / 阿里云 Model Studio WebSocket；北京区价目与上一代 Qwen3.5-LiveTranslate 相同，新加坡区略降（中文二次报道，回链官方）。Demo：https://omni.qwen.ai/live-translate。这不是开源权重，也不是 Omni-Flash 的别名：对会议纪要 / 双语字幕 / 现场同传栈的人，下一轮对账的是说话人 ID 是否进你的字幕时间轴、以及 2.3 秒 LAAL 在嘈杂多说话人场景里能不能稳住，而不是一篇发布稿等于已经替换闭源同传 API。  
来源：Qwen 官方 https://qwen.ai/blog?id=qwen3.8-livetranslate · IT之家 https://www.ithome.com/1/004/450.htm · Demo https://omni.qwen.ai/live-translate
